# 08. セキュリティとリモートアクセス

## 8.1 方針

- **ポート開放ゼロ**。外部からは VPN(Tailscale)経由のみ(D-008)
- **ゼロトラスト内側も**: LAN 内でも Gateway 経由・認証必須(IoT VLAN からは直接触れない)
- **秘密は平文で置かない**。環境変数直書き禁止、秘密管理サービス経由
- **エージェントは最小権限**。6章の権限モデルを基盤で強制

## 8.2 リモートアクセス構成

```
スマホ/PC ── Tailscale(WireGuard) ── studio-a(Tailscale ノード, Subnet Router)
                                        ├─ Gateway(Caddy, 内部 CA で TLS)
                                        ├─ Web UI / API / Home Assistant
                                        └─ 他ノード・NAS へは Subnet Router 経由
```

- Tailscale ACL でデバイスごとに到達可能サービスを制限
- MagicDNS で `ai.<tailnet>.ts.net` 等の名前を付与
- 緊急時の代替: WireGuard 直(ルーターに設定)を用意しておく(→OQ-011)

## 8.3 認証・認可

| 対象 | 方式 |
|---|---|
| Web UI / 管理画面 | OIDC(Pocket-ID/Authelia)+ パスキー |
| API(自作クライアント・IDE) | 個人 API キー(スコープ付き、失効可能) |
| Discord Bot | オーナーの Discord ユーザー ID 固定 + 危険操作は追加確認 |
| ノード間 | SSH 鍵 + Tailscale 認証。RDMA/TB5 は物理的閉域 |

## 8.4 データ保護

- ディスク暗号化(FileVault)全ノード
- Postgres/オブジェクトのバックアップは暗号化して NAS + オフサイト(→OQ-012)
- 会話ログ・ナレッジは「オーナーの最も機微な情報」と位置づけ、アクセスは監査

## 8.5 エージェント固有の脅威と対策

| 脅威 | 対策 |
|---|---|
| プロンプトインジェクション(Web/メール経由) | 外部コンテンツは「データ」として隔離。ツール実行前に権限チェック。Approve レベルは人間承認 |
| 認証情報の漏洩 | エージェントに秘密を渡さず、ツール側で保持(MCP サーバーが代理で認証) |
| 暴走・ループ | トークン/時間予算、ステップ上限、Sentinel による強制停止 |
| サプライチェーン(モデル・OSS) | モデルは Hugging Face の署名/ハッシュ検証、コンテナは固定タグ + 脆弱性スキャン |
