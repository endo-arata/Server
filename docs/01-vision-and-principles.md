# 01. ビジョンと設計原則

## ビジョン

> 自宅に「自分専属のAI研究所 兼 執事」を持つ。
> フロンティア級のオープンモデルを自前で動かし、自分の生活・仕事・知的活動のすべてに
> AIが常駐している状態を作る。データは家から出さない。

## 成功の定義(暫定)

1. **知能**: 1T パラメータ級のオープンモデルを 25 tok/s 以上で常時利用できる
2. **速度**: 日常の会話・コーディング補助は 60 tok/s 以上の中型モデルで即応する
3. **自律性**: 人が何も言わなくても、AIが情報を集め・整理し・提案し・実行し・報告する
4. **遍在性**: スマホ/PC/音声/チャットアプリ/家電のどこからでも同じAIに届く
5. **主権**: モデル・データ・ログのすべてが自宅内に留まり、外部送信はオーナーが明示的に許可したものだけ

## 設計原則

| 原則 | 意味 | 具体例 |
|---|---|---|
| Local-first | 推論・保存・検索はローカル完結が既定 | クラウドAPIは明示オプトインのフォールバック |
| One brain, many faces | 1つのエージェント基盤に複数の入口 | Web UI / Discord / 音声 / API がすべて同じメモリと権限を共有 |
| Memory is the product | 会話・行動・収集情報を構造化して蓄積 | 個人ナレッジグラフ + ベクトル索引 + 時系列ログ |
| Degrade gracefully | 1台落ちても「賢さが下がる」だけで「止まらない」 | 制御プレーンは単一ノードに閉じ、クラスタ推論は縮退モードを持つ |
| Observable by default | 全推論・全ツール実行にトレースを残す | OpenTelemetry + トークン/コスト/レイテンシのダッシュボード |
| Reversible automation | 自律行動は「提案→承認→実行」の段階を持ち、危険操作は必ず承認 | 家電操作・送金・削除は承認必須 |
| Boring infrastructure | 基盤は枯れた技術、AI層は最新を追う | macOS + コンテナ + Postgres。モデルは月次で入れ替え |

## 非目標(やらないこと)

- 不特定多数への公開サービス化(認証・課金・スケールアウトは対象外)
- モデルの事前学習(pre-training)。ただし LoRA/QLoRA 等の軽量ファインチューニングは対象
- Windows/Linux GPU サーバーの追加(現時点)。Apple Silicon に最適化する
- 24/7 のSLA保証。個人利用なので夜間メンテ停止は許容

## リスクと前提

| リスク | 影響 | 対策 |
|---|---|---|
| macOS 26.x の RDMA / MLX 分散はまだ成熟途上 | クラスタ推論の不安定化 | 単一ノード推論を常に維持し、クラスタは「追加の知能」として扱う |
| モデルの世代交代が速い(数ヶ月) | 選定が陳腐化 | モデルは設定ファイル化し、評価ハーネスで入替を自動判定 |
| 2TB SSD × 4 ではモデル置き場が足りない | 1T級 4bit で約600GB | 外付け TB5 NVMe or NAS を追加(→OQ-002) |
| 自律エージェントの暴走 | 誤操作・無駄なリソース消費 | 権限モデル・予算(トークン/時間)・承認ゲートを基盤レベルで強制 |
